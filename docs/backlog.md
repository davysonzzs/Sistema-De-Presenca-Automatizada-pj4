
# 📋 Backlog — Sistema de Presença Automatizada

## Priorização utilizando MoSCoW

| Item | Categoria |
|---|---|
| Testar o reconhecimento dos alunos | Must Have |
| Criar verificação manual quando ocorrerem falhas | Must Have |
| Desenvolver o cadastro dos alunos | Must Have |
| Planejar o envio de notificações aos responsáveis | Must Have |
| Criar orientações para pais e responsáveis | Should Have |
| Fazer orçamento dos equipamentos necessários | Should Have |
| Criar relatórios visuais adicionais | Could Have |
| Desenvolver um aplicativo independente nesta etapa | Won't Have |

## Justificativa

**Must Have:** atividades essenciais para o funcionamento e a confiabilidade do sistema.

**Should Have:** atividades importantes para melhorar a utilização e o planejamento do projeto.

**Could Have:** melhorias adicionais que poderão ser desenvolvidas futuramente.

**Won't Have:** a equipe não desenvolverá um aplicativo independente nesta etapa, pois o foco será desenvolver e validar a solução principal.

## Desempate utilizando RICE

Fórmula:

RICE = (Alcance × Impacto) ÷ Esforço

| Item | Alcance | Impacto (1-3) | Esforço | RICE |
|---|---:|---:|---:|---:|
| Testar o reconhecimento dos alunos | 100 | 3 | 4 | 75 |
| Criar relatórios visuais adicionais | 50 | 2 | 3 | 33,33 |

### Cálculos

**Testar o reconhecimento:**

(100 × 3) ÷ 4 = 75

**Criar relatórios visuais:**

(50 × 2) ÷ 3 = 33,33

### Conclusão

O resultado confirmou a prioridade de testar o reconhecimento dos alunos, pois essa atividade possui maior impacto na confiabilidade do sistema e alcança mais pessoas.

**Observação:** os valores são estimativas para o exercício e devem ser discutidos e validados pela equipe, especialmente porque os dois itens precisam representar aqueles que geraram maior discordância.
